www.nba.com postMessage Origin Validation Bypass (CWE-346)

This page (hosted on a completely unrelated origin, e.g. GitHub Pages) opens www.nba.com and sends it a crafted postMessage. The receiving handler on nba.com performs no check of the sender's origin — it only checks that the message body contains isStorytellerMessage: true, a flag the sender fully controls. If accepted, nba.com dispatches a real DOM CustomEvent — with an attacker-chosen name and payload — on document.body, which any code on the page (not just the intended widget) can act on.

Steps:

  1. Click "Open target + attack" below. This opens https://www.nba.com/ in a new tab (simulating a victim who already has NBA.com open, or clicks a link to it from this page).
  2. Wait for it to finish loading (~4s), then this page automatically sends the crafted message.
  3. Switch to the NBA.com tab and open DevTools → Console. Run the verification snippet at the bottom of this page there to see the injected event landing in the page's real event bus. (A genuinely cross-origin attacker cannot read the result back into this page due to the Same-Origin Policy — this is why step 3 is a manual verification step, exactly like a real attacker would only know the injection worked once its real-world side effect fires, e.g. a visible UI change in an actively-rendered widget.)
